# BoltBox 부품재고

재고 데이터는 BoltBox **API로만** 조회하고 변경한다. 이 Skill은 API를 **언제, 어떤 순서로, 어떤 규칙으로** 부르는지 정리한 사용 설명서다.

품목은 약 3,000개다(볼트·너트·베어링·오링·피팅·센서 등). **전체 목록을 한 번에 읽지 않는다.** 항상 검색하거나 부족 품목만 조회한다.

## 연결

- 주소: `http://127.0.0.1:8000` (이 PC에서만 열린다)
- 시작할 때 `curl.exe -s http://127.0.0.1:8000/api/health`로 켜져 있는지 확인한다. `{"ok": true, ...}`가 오면 준비된 것이다.
- 응답이 없으면 BoltBox에 연결할 수 없다고 알리고, 서비스가 켜져 있는지 확인해 달라고 요청한다. 다른 주소·포트를 추측해서 부르지 말고 사용자에게 묻는다.
- 사용법을 잊었으면 `GET /api`를 부른다. 주소와 보낼 값 목록이 나온다.

## API

`curl.exe`로 부른다(PowerShell의 `curl`은 다른 명령의 별칭이라 쓰지 않는다. macOS·Linux에서는 `curl`).
한글·공백이 들어간 값은 반드시 `--data-urlencode "이름=값"`으로 보내고, 숫자·영문 값은 `-d 이름=값`으로 보낸다.
조회(GET)는 `-G`를 붙인다.

| 하려는 일 | 호출 |
|---|---|
| 현황 요약 (전체·부족 개수, 오늘 입출고 건수) | `curl.exe -s http://127.0.0.1:8000/api/summary` |
| 품목 검색 | `curl.exe -s -G http://127.0.0.1:8000/api/items --data-urlencode "q=베어링 6204"` |
| 안전재고 미만 (급한 순) | `curl.exe -s -G http://127.0.0.1:8000/api/items -d low=1 -d limit=20` |
| 분류 안에서 부족 품목 | `curl.exe -s -G http://127.0.0.1:8000/api/items -d low=1 --data-urlencode "q=오링"` |
| 입고 | `curl.exe -s http://127.0.0.1:8000/api/in --data-urlencode "name=정확한 품목명" -d qty=수량 [--data-urlencode "note=메모"]` |
| 거래명세서 읽기 | `curl.exe -s http://127.0.0.1:8000/api/read --data-urlencode "path=파일 전체 경로"` (.xlsx, .csv, .pdf) |
| 명세서 중복 확인 | `curl.exe -s -G http://127.0.0.1:8000/api/history --data-urlencode "note=명세서 번호" -d limit=100` |
| 출고 | `curl.exe -s http://127.0.0.1:8000/api/out --data-urlencode "name=정확한 품목명" -d qty=수량` |
| 품목 추가 | `curl.exe -s http://127.0.0.1:8000/api/add --data-urlencode "name=품목명" -d qty=수량 -d min=안전재고 --data-urlencode "unit=단위"` |
| 안전재고 변경 | `curl.exe -s http://127.0.0.1:8000/api/min --data-urlencode "name=정확한 품목명" -d min=수량` |
| 품목 삭제 | `curl.exe -s http://127.0.0.1:8000/api/remove --data-urlencode "name=정확한 품목명"` |
| 입출고 기록 | `curl.exe -s -G http://127.0.0.1:8000/api/history [--data-urlencode "name=정확한 품목명"] -d limit=20` |

- 조회는 `GET`, 변경은 `POST`다. `-G` 없이 `-d`/`--data-urlencode`를 붙이면 `POST`가 된다.
- `/api/items`의 결과는 `{"total": 전체 개수, "shown": 표시 개수, "items": [...]}`이다. 기본 50개까지만 나온다.
- `q`는 공백으로 나눈 단어가 **모두** 들어 있는 품목을 찾는다. `"베어링 6204"`는 `베어링 6204`, `베어링 6204ZZ`, `베어링 6204-2RS`를 찾는다.
- 변경 호출은 성공하면 바뀐 품목 `{name, qty, min, unit, low}`를 돌려준다. 변경 후 수량은 이 값을 쓴다.
- 실패하면 `{"error": "..."}`가 온다. 오류 내용을 그대로 사용자에게 알린다.

## 절차

1. **요청 파악** — 조회, 입고, 출고, 추가, 삭제 중 무엇인지 정한다.
2. **품목 찾기** — 사용자가 말한 이름으로 `/api/items?q=`를 부른다.
   - 결과가 1개면 그 품목을 쓴다.
   - 여러 개면 후보를 표로 보여 주고(10개 이내) 어느 것인지 묻는다. 변경 호출은 품목이 정해지기 전에 하지 않는다.
   - 너무 많으면(`total`이 10 초과) 규격(크기·재질·형번)을 더 물어본다.
   - 0개면 단어를 줄이거나 바꿔 한 번 더 검색하고, 그래도 없으면 없다고 알린다.
3. **실행 전 점검** — 출고라면 현재 재고가 충분한지 먼저 본다. 부족하면 호출하지 않고 현재 수량을 알린다.
4. **실행** — 변경 호출은 한 번에 하나씩, 정확한 품목명으로 한다.
5. **결과 보고** — 변경 전후 수량을 표로 보여 준다. 결과가 안전재고 미만이면 "부족"이라고 함께 알린다.

## 거래명세서로 입고하기

사용자가 거래명세서·납품서 파일을 주고 입고를 요청하면 이 순서를 따른다.

1. **파일 읽기** — `/api/read`로 읽는다. 결과는 시트(PDF는 쪽)별 행 목록이다. 첨부 파일이면 첨부된 파일의 전체 경로를 그대로 쓴다.
   - PDF는 두 칸 이상 띄어진 곳을 칸 경계로 나눈 결과라, 칸이 합쳐지거나 밀릴 수 있다. 행 전체를 보고 품명·규격·단위·수량을 판단한다.
   - `pypdf가 필요합니다` 오류가 나면 그 안내를 사용자에게 그대로 전하고, BoltBox 쪽 설치가 끝난 뒤 다시 시도한다.
2. **명세서 정보 찾기** — 명세서 번호, 거래일자, 공급자를 찾는다. 품목 표에서 행마다 품명, 규격, 단위, 수량을 뽑는다. 합계·세액 행은 품목이 아니다.
3. **중복 확인** — `/api/history?note=명세서 번호`로 이미 입고한 명세서인지 본다. 기록이 있으면 입고하지 않고 언제 처리됐는지 알린다.
4. **품목 맞추기** — 명세서 표기는 재고 품목명과 다를 수 있다. 다음처럼 정리해서 `q`로 검색한다.
   - `×` → `x` (예: `M6×20` → `M6x20`)
   - 형번 사이 공백 제거 (예: `6204 ZZ` → `6204ZZ`)
   - 괄호 제거 (예: `P20 (NBR)` → `P20 NBR`)
   - `Ø8` → `8mm`, `플랜지형` → `플랜지`, `육각볼트` → `볼트`
   - 품명 괄호 속 형태는 따로 떼기 (예: `원터치피팅(엘보)` + `Ø6 × PT1/4` → `원터치피팅 엘보 6mm PT1/4`)
   - 벨트 표기: `15W` → `15폭`, `L600` → `600mm`
   - 핀 표기: `Ø5×20` → `5x20`, 전선 `0.5SQ` → `0.5sq`
   - 단위 `EA` → `개`, `M` → `m`
   - 검색 결과가 0개면 표기를 바꿔(단어 줄이기, 기호 빼기) 한 번 더 검색한 뒤 **미등록**으로 판단한다.
   - 결과가 1개이고 규격이 모두 맞으면 **매칭**, 후보가 여럿이거나 규격이 다르면 **확인 필요**, 0개면 **미등록**으로 분류한다.
5. **입고 계획 보여 주기** — 아래 표를 보여 주고 **확인을 받은 뒤** 진행한다. 문서 입고는 항상 확인을 받는다.

   ```
   명세서 TS-20261026-01 · 2026-10-26 · (주)한빛기계상사
   | No | 명세서 품목 | 재고 품목 | 수량 | 현재 → 입고 후 | 상태 |
   |---|---|---|---|---|---|
   | 1 | 베어링 6204 ZZ | 베어링 6204ZZ | 20개 | 8 → 28 | 매칭 |
   | 8 | LM부시 LM12 플랜지형 | — | 4개 | — | 미등록 |
   ```
6. **입고 실행** — 확인을 받으면 **매칭** 품목만 하나씩 `/api/in`에 `name`, `qty`, `note=명세서 번호`를 보내 입고한다.
7. **결과 보고** — 처리한 품목의 변경 전후 표를 보여 준다. **미등록**·**확인 필요** 품목은 따로 모아 알리고, 품목을 새로 추가할지 묻는다.

- 수량은 명세서에 적힌 값만 쓴다. 단가·금액은 재고에 반영하지 않는다.
- 표의 단위는 **재고 품목의 단위**(`unit`)로 적는다. 예: 케이블은 `m`, 그리스·윤활유는 `통`.
- 품목마다 `/api/in`은 **한 번만** 부른다. 성공한 호출은 다시 하지 않는다. 결과가 불확실하면(응답이 끊기는 등) 다시 입고하지 말고 `/api/history?note=`로 먼저 확인한다.
- `이미 입고된 항목입니다` 오류가 나면 그 품목은 처리된 것으로 보고 넘어간다. `allow_duplicate=1`은 사용자가 명시적으로 요청할 때만 보낸다.
- 미등록 품목은 사용자가 요청하기 전에는 `/api/add`하지 않는다.

## 규칙

- 숫자는 반드시 API 응답에서 가져온다. 추측하거나 계산해서 지어내지 않는다.
- 부족 품목을 물으면 `total`(전체 부족 개수)을 먼저 말하고, 급한 순 상위 10~20개만 보여 준 뒤 더 볼지 묻는다.
- BoltBox의 데이터 파일을 직접 열어 고치거나 다른 경로로 우회하지 않는다. 조회와 변경은 항상 API로 한다.
- 실수로 잘못 처리했다면 바로잡기 전에 **무엇이 잘못됐는지 사용자에게 알리고** 확인을 받는다. 정정한 내용도 결과 보고에 포함한다.
- 다음 작업은 **먼저 무엇을 할지 보여 주고 확인을 받은 뒤** 실행한다.
  - 품목 삭제
  - 한 번에 3개 이상의 품목 변경
  - 수량 100 이상의 입고·출고

## 결과 형식

```
| 품목 | 변경 전 | 변경 후 | 안전재고 | 상태 |
|---|---|---|---|---|
| 베어링 6204ZZ | 8개 | 5개 | 10개 | 부족 |
```

조회만 했을 때는 `품목 | 재고 | 안전재고 | 상태` 표로 보여 준다.

수업 전 준비

  1. 참여자 PC에서 ssh -V를 확인합니다. 필요한 경우 OpenSSH Client 설치를 사전에 지원합니다.
  2. 강사 PC를 수업 네트워크에 연결해 실제 Bandit SSH 접속을 확인합니다. TCP 연결만의 성공과 SSH 로그인을 구분합니다.
  3. 접속 대상과 서버 지문을 신뢰할 수 있는 경로로 확인합니다. 지문 변경 경고는 임의로 무시하지 않습니다.
  4. 최신 공식 문제와 시작 계정을 확인합니다. 실제 비밀번호는 자료나 저장소에 기록하지 않습니다.
  5. week3.html, PowerShell, 공식 문제, worksheet.html을 준비합니다.
  6. 연결이 어려운 경우 practice/terminal.html의 자체 모의 환경으로 전환합니다. 실제 SSH 연결은 별도 보충합니다.

진행 기준

기본 목표는 bandit3 계정 로그인입니다. 접속에 시간이 걸리면 bandit1 로그인과 명령 설명을 우선합니다. 점수 경쟁보다 현재 위치, 사용한 명령, 결과를 설명하는 데 집중합니다.

과제 설명과 비밀번호를 자료에 복제하지 않습니다. 문제는 OverTheWire 공식 링크에서 읽고, 개인 풀이 메모에는 명령과 이유를 남깁니다. 학생용 기록지에는 비밀번호 칸이 없습니다.

클릭과 명령어

GUI는 버튼과 메뉴로, CLI는 텍스트 명령으로 컴퓨터를 사용합니다. 둘 다 파일을 읽는 일을 할 수 있습니다. CLI에서는 어떤 작업을 했는지가 명령어로 남고, 같은 절차를 다시 실행하기 쉽습니다. 이 화면의 notes와 welcome.txt는 우리가 만든 연습기 파일입니다.

SLIDE 04 · 3–5분

터미널과 셸

터미널은 창이고 셸은 명령을 해석하는 프로그램입니다. Windows Terminal이나 VS Code 터미널에서 PowerShell을 사용할 수 있습니다. 여기서 ssh를 실행하면 다른 컴퓨터의 셸과 대화하게 됩니다. 같은 창을 계속 쓰더라도 명령이 실행되는 컴퓨터는 달라집니다.

진행: PowerShell 프롬프트를 먼저 보여 줍니다. 아직 SSH로 접속하지 않은 상태라는 것을 확인합니다.

질문: 터미널 창이 같으면 실행되는 컴퓨터도 같을까요?
예상 답: 아닙니다. SSH 접속 뒤에는 원격 셸에서 명령을 실행할 수 있습니다.

참고: OpenSSH ssh 매뉴얼 Microsoft OpenSSH 시작하기

SLIDE 05 · 5–7분

지금 어느 컴퓨터인가

로컬은 지금 사용 중인 내 PC이고 원격은 네트워크로 접속한 다른 컴퓨터입니다. 접속 후 cat으로 읽는 파일은 서버의 파일입니다. 내 PC의 바탕화면 파일이 자동으로 서버에 복사되는 것은 아닙니다. 서버에서 파일을 바꾸는 명령을 실행하면 서버 파일에 영향을 줍니다.

진행: 프롬프트의 PS 경로와 bandit 계정 표기를 가리킵니다.

질문: SSH로 접속한 뒤 pwd는 어느 컴퓨터의 경로를 보여 줄까요?
예상 답: 원격 서버에서 실행 중인 셸의 현재 작업 경로입니다.

참고: OpenSSH ssh 매뉴얼

SLIDE 06 · 7–9분

SSH로 할 수 있는 일

SSH는 원격 로그인에 사용하는 프로토콜입니다. 통신을 암호화하고, 로그인한 계정의 권한 안에서 명령을 실행합니다. 회사의 리눅스 서버나 라즈베리파이를 관리할 때도 같은 방식으로 접속할 수 있습니다. 오늘은 Bandit 연습 서버에서 파일을 읽는 범위로 실습합니다.

진행: 자신이 사용해 본 원격 PC나 서버 예시가 있는지 한 명에게 물어봅니다.

참고: OpenSSH ssh 매뉴얼 OverTheWire Bandit

SLIDE 07 · 9–10.5분

SSH 명령 읽기

ssh는 프로그램 이름입니다. 소문자 p 옵션 뒤에는 포트를 적습니다. 골뱅이 앞은 사용자 이름이고 뒤는 서버 주소입니다. Bandit은 2220 포트를 사용합니다. 포트는 이 서버에서 어떤 서비스에 연결할지를 구분하는 번호라고 이해하면 됩니다.

진행: 명령에서 계정과 주소를 각각 가리킵니다. 다음 단계에서는 bandit0 부분만 바뀝니다.

SLIDE 08 · 10.5–11.5분

접속 준비

먼저 ssh 대문자 V로 버전을 확인합니다. 버전 출력은 클라이언트가 있다는 뜻이며 서버 접속 성공을 뜻하지는 않습니다. 접속용 PC에는 OpenSSH Client를 확인합니다. 설치가 필요한 참여자는 수업 전에 지원합니다.

진행: 참여자에게 ssh -V를 실행하게 합니다. 설치 문제는 휴식 시간에 지원하고 수업을 오래 멈추지 않습니다.

참고: Microsoft OpenSSH 시작하기 OpenSSH ssh 매뉴얼

SLIDE 09 · 11.5–13.5분

처음 접속할 때

처음 보는 서버이면 호스트 키 지문을 확인하는 질문이 나올 수 있습니다. 강사는 수업 전에 접속 대상과 지문을 신뢰할 수 있는 경로로 확인하고 안내합니다. 주소와 지문 확인 후 승인하고, 공식 시작 페이지의 비밀번호를 입력합니다. 화면에 입력이 안 보이는 것은 일반적인 비밀번호 입력 방식입니다. 이전과 키가 다르다는 경고는 임의로 무시하지 말고 강사와 확인합니다.

진행: 실제 로그인 시연에서 비밀번호는 화면과 자료에 남기지 않습니다. 최초 승인과 비밀번호 입력이 서로 다른 단계임을 설명합니다.

참고: OpenSSH ssh 매뉴얼 Bandit Level 0

SLIDE 10 · 13.5–14.5분

접속 상태 확인

접속이 되었는지 문구만 보고 지나가지 말고 실제 상태를 확인합니다. whoami는 사용자, hostname은 컴퓨터 이름, pwd는 현재 작업 경로를 보여 줍니다. 컴퓨터 이름은 실제 서버 설정에 따라 달라질 수 있습니다.

진행: 세 명령을 실행하고 출력 중 계정과 경로를 직접 읽어 보게 합니다.

질문: bandit1로 다시 접속했다면 어떤 출력이 바뀔까요?
예상 답: 사용자 이름과 일반적으로 홈 경로가 바뀝니다. 접속한 서버 자체는 같을 수 있습니다.

참고: OpenSSH ssh 매뉴얼

SLIDE 11 · 14.5–16.5분

현재 위치와 파일 목록

여기부터는 자체 연습기에서 동일한 파일을 보며 명령의 의미를 확인합니다. 실제 Bandit의 파일 목록과는 다릅니다. pwd를 먼저 실행해서 현재 위치를 확인하고 ls로 목록을 확인합니다. 폴더도 파일 목록에 함께 나옵니다.

진행: practice/terminal.html을 열고 pwd와 ls를 입력합니다. 브라우저 내부의 모의 환경임을 분명히 알립니다.

참고: GNU Coreutils ls

SLIDE 12 · 16.5–18.5분

폴더 이동과 경로

cd는 현재 디렉터리를 바꿉니다. cd notes는 지금 위치 아래의 notes로 이동하는 상대 경로입니다. 슬래시로 시작하는 경로는 루트에서 시작하는 절대 경로입니다. 점 두 개는 상위 폴더이고 물결표는 홈 폴더입니다. 같은 명령도 현재 위치에 따라 결과가 달라질 수 있습니다.

진행: cd notes 뒤에 pwd를 실행해 경로 변화를 확인하고 cd .., cd ~를 실행합니다.

질문: notes 폴더 안에서 다시 cd notes를 실행하면 어떻게 될까요?
예상 답: 그 안에 notes 폴더가 없다면 경로를 찾지 못합니다. 먼저 pwd와 ls로 확인합니다.

SLIDE 13 · 18.5–19.5분

파일 내용 읽기

cat은 텍스트 내용을 화면에 출력할 때 사용할 수 있습니다. 이 실습에서는 내용을 읽기만 합니다. No such file or directory가 나오면 먼저 현재 위치와 파일 이름을 확인합니다. 리눅스에서 일반적으로 파일 이름의 대소문자는 구분합니다.

진행: cat welcome.txt를 실행한 뒤 의도적으로 대소문자를 바꾸어 오류를 보여 주고 원인을 찾습니다.

참고: GNU Coreutils cat

SLIDE 14 · 19.5–20.5분

명령과 옵션

옵션은 같은 명령의 동작을 조절합니다. ls에 a 옵션을 붙이면 점으로 시작하는 파일도 볼 수 있고 l 옵션을 붙이면 자세한 정보를 볼 수 있습니다. 두 옵션은 la로 함께 쓸 수 있습니다. 오늘은 모든 열을 외우지 말고 출력이 어떻게 달라지는지 관찰합니다.

진행: 연습기의 notes 폴더에서 ls와 ls -la를 비교합니다.

참고: GNU Coreutils ls

SLIDE 15 · 20.5–21.5분

도움말과 입력 조작

모르는 명령은 매뉴얼과 도움말에서 찾습니다. man 화면에서는 q로 나올 수 있습니다. cd는 Bash 내장 명령이라 help cd로 확인할 수 있습니다. Tab과 위쪽 화살표를 쓰면 입력을 줄일 수 있습니다. Ctrl+C는 실행 중인 작업이나 입력 대기를 중단할 때 씁니다. 터미널별 복사와 붙여넣기 단축키는 다를 수 있습니다.

진행: 실제 Bandit 셸에서 man ls를 열고 q로 닫는 모습을 짧게 보여 줍니다. 자체 연습기의 man은 축약 도움말이라고 안내합니다.

참고: OverTheWire Bandit

접속 종료와 재접속

exit는 지금 원격 셸을 끝냅니다. 내 PC의 프롬프트로 돌아왔는지 확인하고 다음 계정에 접속합니다. 오늘은 서버 안에서 다시 SSH를 여러 겹으로 여는 방식 대신, 종료 후 내 PC에서 다음 계정으로 접속하는 흐름을 사용합니다.

진행: 실제 bandit0에서 exit 후 로컬 프롬프트를 확인합니다. 이 시점에 bandit1 비밀번호가 없으므로 다음 접속 명령의 구조만 설명합니다.

파일 이름의 공백과 기호

공백이 있는 이름은 따옴표로 묶습니다. 따옴표만으로 옵션처럼 시작하는 이름의 해석까지 바뀌지는 않으므로 ./로 현재 폴더의 경로를 적으면 명확합니다. 특히 cat은 단독 하이픈을 표준 입력으로 해석합니다. 옵션 종료를 뜻하는 --를 추가해도 단독 하이픈의 특별한 뜻은 남습니다. cat ./-로 파일 경로를 지정하면 됩니다. cat이 입력을 기다릴 때는 Ctrl+C로 중단합니다.
